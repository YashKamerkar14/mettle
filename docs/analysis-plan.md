# Analysis plan (pre-registered)

**Status: DRAFT, ready to freeze.** Freezing means committing this file with the status line changed to "FROZEN on <date>" *before* the full reference run on `eval/questions/questions.v1.jsonl`. After that it is not edited; any change goes in "Deviations" at the bottom, dated, with the reason.

## Questions

1. **Compression trade-off.** On a fixed question set, how much faster is the 4-bit build (q4f16_1) than full precision (q0f16), and how many points of accuracy does it lose?
2. **Cross-device consistency.** For a fixed build, on what share of devices does the model reproduce the reference outputs exactly, and where it does not, at which token does output first diverge?

## Fixed settings

- Model: SmolLM2-360M-Instruct, WebLLM 0.2.86 builds q4f16_1, q4f32_1, q0f16, q0f32.
- Code path: `web/src/quality/runQuestions.ts`, driven by `eval/reference.mjs` for reference runs and by the site for visitors.
- Each question is a single user message from an empty conversation (`resetChat`), greedy decoding (temperature 0), `max_tokens` 16, logprobs with top-2 alternatives recorded.
- Reference device: the author's RTX 4080 Laptop GPU, Chrome, `--force_high_performance_gpu`.

## Question set

`eval/questions/questions.v1.jsonl`, generated by `eval/questions/build.py` (seed 20261012). 500 items, 100 per category:

| Category | What it tests | Scorer |
| --- | --- | --- |
| arithmetic | two-digit addition and subtraction | number |
| compare | "which is larger/smaller" of two two-digit numbers | number |
| capital | capital city of a country (ambiguous cases excluded) | phrase |
| antonym | one-word opposite (several accepted answers) | phrase |
| sentiment | short review, positive / negative; a quarter use negation | label |

## Scoring (`eval/analysis/scoring.py`)

- **Primary ("answer correct").** Take the first non-empty line. If it contains an answer marker (` is `, `=`, `:`), keep only the text after the last one. Normalise (lowercase, strip accents, delete quotes and apostrophes, other punctuation to spaces). Correct if it exactly equals an accepted answer; for numbers, if it parses as a single integer equal to the key.
- **Secondary ("followed format").** Same, but the whole first line must equal the answer, with no extraction. This measures whether the model obeyed "answer with only ...".

Why primary uses extraction: in the pilot, the 4-bit build answered in full sentences ("The capital of Iceland is Reykjavik.") far more often than full precision. Without extraction, the comparison would mostly measure wordiness rather than knowledge. Both scores are reported.

## Primary metrics and tests

| Question | Metric | Interval / test |
| --- | --- | --- |
| Accuracy per build | proportion correct (primary and secondary) | Wilson 95% CI |
| Accuracy lost by 4-bit | paired difference q0f16 − q4f16_1 on the same items | exact McNemar test; paired bootstrap 95% CI (10,000 resamples, seed 0) |
| Where 4-bit hurts | per-category difference | same, Holm-corrected across the 5 categories |
| Speed gained by 4-bit | ratio of median decode tok/s, same device and session | bootstrap CI across the author's devices |
| Device consistency | share of devices whose outputs match the reference on all items of the in-browser subset, per build | Wilson 95% CI |
| Drift location | first divergent token index; reference build's top-1 vs top-2 log-prob margin at that token | descriptive |

## Decisions made in advance

- **Determinism baseline.** The full reference run is done twice per build on the reference device. If any output differs between the two, same-device nondeterminism is reported first and cross-device differences are not attributed to hardware.
- **Builds are compared within compute type.** f16 devices are compared against f16 references, f32 against f32. The headline trade-off uses the f16 builds; the f32 pair is reported as a robustness check.
- **Exclusions for crowd results:** instant-score CPU check failed; any timing non-positive; decode speed above 2,000 tok/s; runtime, question-set or prompt version different from the reference.
- **Null results are reported.** If 4-bit costs no measurable accuracy (CI includes 0) or all devices agree, that is the finding.

## Calibration (done before freezing)

Rule: on a separate 48-item pilot (`eval/questions/pilot.v1.jsonl`, 8 per category, disjoint from the main set), drop any category where q0f16 scores below 25% or above 95% (primary score).

Pilot run on 2026-10-12 (`eval/results/pilot/report.md`):

| Category | q0f16 | Decision |
| --- | --- | --- |
| antonym | 87.5% | keep |
| arithmetic | 87.5% | keep |
| capital | 62.5% | keep |
| compare | 62.5% | keep |
| sentiment | 75.0% | keep |
| sequence (days, months, letters, number patterns) | 0.0% | **dropped** |

The pilot also showed identical outputs on 48/48 items across two runs of each build on the reference device. The scoring rule above was written after seeing the pilot outputs; pilot items are not part of the main set.
